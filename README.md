# Кейс: Мобильное приложение «Мой оператор связи»
(аналог “Мой МТС” или “Мой ТЕЛЕ2” с минимальной функциональностью)

## Контекст: 
Заказчик - компания, предоставляющая услуги сотовой связи физическим лицам. 

Необходимо разработать мобильное приложение, в котором абонент сможет:
- проверить свой баланс,
- просмотреть все тарифы,
- изменить текущий тариф.

## Краткое описание системы:
Проектирование мобильного приложения для абонентов оператора связи, которое позволяет самостоятельно управлять услугами (проверка баланса, смена тарифа, подключение/отключение опций, пополнение счёта) без обращения в контакт-центр. Цель — снизить нагрузку на поддержку на 25% и повысить долю самообслуживания.

## Что сделала:

- Интервью со стейкхолдерами: провела серию интервью с тремя группами респондентов (представитель бизнеса / Product Owner, абонент-конечный пользователь, сотрудник контакт-центра). Сформулировала цели, задачи, KPI, риски и функциональные приоритеты.

- Use Case-моделирование: выделила 10 ключевых вариантов использования (UC-01 — UC-10), описала основные, альтернативные и исключительные потоки для каждого. Построила Use Case Diagram с отображением внешних систем.

- Требования: разработала полную спецификацию — бизнес-требования (FBR), пользовательские (FUR), функциональные (FFR), нефункциональные (NFR, NSR, NQA, NIR, NCO) с приоритетами и метриками.

- Диаграмма классов: спроектировала модель данных из 13 сущностей (Contract, Customer, Passport, Tariff, Option, Payment, Address и др.), с обоснованием выбора типов данных, связей и ограничений.

- OpenAPI-спецификация: описала объекты и ресурсы, акторов, методы API, параметры запросов и ответов. Реализовала асинхронные операции (смена тарифа, управление опциями), 2FA для критических операций, пагинацию, стандартизированную обработку ошибок (ErrorResponse).

- Документация: подготовила SRS по шаблону Карла Вигерса.
